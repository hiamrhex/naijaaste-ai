## Findings considered and rejected

- **Layers 3–7 (auth cluster)**: no user accounts exist; UUID session ids act as capability
  tokens (122 bits of entropy — guessing infeasible). Adding JWT/session auth to a public demo
  adds attack surface with no subject to authenticate. Revisit when user accounts ship.
- **Layer 9**: already satisfied — `uuidv4()` at `src/routes/chat.routes.js:20`,
  `src/services/chat.service.js:139`, `src/routes/persona.routes.js:84`.
- **Layers 10/11/13/14/17 (DB durability, transactions, checksums, money, currency)**: no
  database or payments; a single-process JSON store with a serialized write queue
  (`src/services/chat.service.js:16-53`) is proportionate.
- **Layer 12 (optimistic concurrency)**: all writes are serialized by the in-process queue;
  multi-writer N/A until a real database.
- **Layer 5 (timing-safe compare)**: no secret comparisons exist in app code.
- **Layer 25 (versioned path prefix)**: the deployed frontend hard-codes absolute API URLs
  (`src/constants/index.js:3`) — introducing `/api/v1` breaks the live UI until a coordinated
  frontend redeploy. Revisit when the API gains external consumers.
- **Layer 28 (roles)**: no users → N/A.
- **Helmet/security headers**: not part of the 25-layer checklist and the frontend is served
  as a separate static app. Re-audit if this server starts serving the built frontend.
- **CI**: not rejected — included in plan 002; a verification gate that never runs is not a gate.
