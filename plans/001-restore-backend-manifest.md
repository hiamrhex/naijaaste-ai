## Why this matters

Commit `b739eff` replaced the backend `package.json` with a stock Vite/React
manifest, dropping the five runtime dependencies the Express server needs
(`express`, `cors`, `dotenv`, `uuid`, `groq-sdk`). The server therefore cannot
boot, `node src/app.js` fails at the first import, and the Dockerfile's
`npm ci --only=production` installs nothing the server uses. Every later plan
(verification, contracts, logging) is blocked until the manifest is whole
again. The original backend manifest is preserved in git history, so this is a
merge, not a guess.

### Step 3: Boot smoke test

The server must import cleanly and serve `/health`. A `GROQ_API_KEY` value must
be present at import time (`src/services/llm.service.js:3` constructs the Groq
client eagerly) — use a dummy: no API call happens at boot.

PowerShell (run from repo root; if a `.env` exists its real key is used instead,
which is also fine):

```powershell
$env:GROQ_API_KEY = 'dummy-key-for-smoke-test'
$p = Start-Process node -ArgumentList 'src/app.js' -PassThru -WindowStyle Hidden
Start-Sleep -Seconds 3
try { $r = Invoke-WebRequest -Uri http://localhost:3000/health -UseBasicParsing; "HTTP $($r.StatusCode)" }
finally { Stop-Process -Id $p.Id -Force -ErrorAction SilentlyContinue }
```

POSIX equivalent:

```bash
GROQ_API_KEY=dummy-key node src/app.js & sleep 3; curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/health; kill %1
```

**Verify**: prints `HTTP 200` (or `200`). If the boot fails with
`EADDRINUSE`, another server owns port 3000 — stop it and retry once.

### Step 4: Dockerfile flag

`--only=production` is deprecated; replace line 7 with:

```dockerfile
RUN npm ci --omit=dev
```

**Verify**: `Select-String -Path Dockerfile -Pattern 'omit=dev'` → one match.
If docker is available (`docker --version` exits 0): `docker build -t naijataste:001 .`
→ exit 0. If docker is not installed, record "docker unavailable — build skipped"
in your completion report and continue (this is the only sanctioned skip).
